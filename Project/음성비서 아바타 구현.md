원인이 확인됐습니다. 현재 로그의 **핵심 오류는 `/api/session 400`**이고, 제가 처음 제공한 코드의 리소스 검사가 너무 엄격했습니다.

Perso SDK 기준으로 `createSessionId()`에서 **`model_style`과 `prompt`는 필수**지만 `llm_type`, `tts_type`, `stt_type`은 선택 항목입니다. 기존 코드는 다섯 항목을 모두 필수로 검사했습니다.

수정한 프로젝트입니다.

**[📦 perso-weather-assistant-v2.zip 다운로드](sandbox:/mnt/data/perso-weather-assistant-v2.zip)**

### 1. 기존 코드의 문제

기존에는 다음과 같았습니다.

```javascript
if (!model) missing.push("model_style");
if (!prompt) missing.push("prompt");
if (!llm) missing.push("llm_type");
if (!tts) missing.push("tts_type");
if (!stt) missing.push("stt_type");

if (missing.length) {
    return res.status(400).json({
        error: "Perso 계정에서 필요한 리소스를 찾지 못했습니다."
    });
}
```

예를 들어 Perso 계정이 다음처럼 조회되면:

```text
Model Style : 있음
Prompt      : 있음
LLM         : 없음
TTS         : 있음
STT         : 있음
```

세션 자체를 만들 수 있는 상황인데도 제가 작성한 코드에서는 **400 오류를 강제로 발생**시켰습니다.

수정 버전은:

```javascript
const missingRequired = [];

if (!model) missingRequired.push("model_style");
if (!prompt) missingRequired.push("prompt");
```

두 개만 필수 검사합니다.

나머지는 존재할 때만 전달합니다.

```javascript
const params = {
    using_stf_webrtc: true,
    model_style: model.name,
    prompt: prompt.prompt_id
};

if (llm) params.llm_type = llm.name;
if (tts) params.tts_type = tts.name;
if (stt) params.stt_type = stt.name;
```

Perso의 공식 샘플도 `createSessionId()`에서 선택한 Model Style, Prompt, LLM, TTS, STT 리소스를 조합해 세션을 생성하는 구조를 사용합니다.

## 2. 이번에는 진단 기능도 추가했습니다

새 버전을 실행한 뒤 다음 주소를 브라우저에 입력해 주세요.

```text
http://localhost:5173/api/perso-settings
```

Perso API Key에서 실제로 조회되는 리소스가 표시됩니다.

정상적인 경우 예를 들면:

```json
{
  "counts": {
    "modelStyles": 2,
    "prompts": 1,
    "llms": 3,
    "ttsTypes": 4,
    "sttTypes": 2
  },

  "modelStyles": [
    {
      "name": "..."
    }
  ],

  "prompts": [
    {
      "name": "weather-helper",
      "prompt_id": "..."
    }
  ],

  "llms": [
    {
      "name": "..."
    }
  ],

  "ttsTypes": [
    {
      "name": "..."
    }
  ],

  "sttTypes": [
    {
      "name": "..."
    }
  ]
}
```

Perso SDK의 `getAllSettings()`는 실제로 LLM, TTS, STT, Model Style, Prompt 등의 설정 목록을 가져오는 기능을 제공합니다.

### 여기서 가장 중요하게 볼 값

```text
modelStyles > 0
prompts     > 0
ttsTypes    > 0
sttTypes    > 0
```

입니다.

우리 프로젝트는 LLM을 직접 사용하지 않고:

```text
STT
 ↓
Weather API
 ↓
응답문 생성
 ↓
TTS
 ↓
Avatar Lip Sync
```

구조이므로 **LLM이 0이어도 핵심 날씨 서비스 로직 자체에는 문제가 없습니다.**

반면:

```json
"modelStyles": 0
```

이면 **Perso 아바타/Model Style이 계정에 할당되지 않은 것**이라 코드만으로 해결할 수 없습니다.

또:

```json
"prompts": 0
```

이면 Perso Platform에서 Prompt를 하나 생성해야 합니다.

예:

```text
Name
weather-helper
```

System Prompt:

```text
당신은 날씨 안내 서비스 도우미입니다.
한국어로 친절하고 간단하게 응답합니다.
```

# 4. 나머지 콘솔 오류는 이렇게 보면 됩니다

### `favicon.ico 404`

```text
:5173/favicon.ico
Failed to load resource: 404
```

이것은 **무시해도 됩니다.**

브라우저 탭 아이콘 파일을 만들지 않아서 나타난 것입니다. Perso나 STT/TTS와 관계없습니다.

---

### `searchitfastnow.com ... CORS`

이 오류는 더 주의해서 볼 필요가 있습니다.

```text
Access to fetch at
'https://searchitfastnow.com/switch_av_odm.php?...'
from origin 'http://localhost:5173'
has been blocked by CORS policy
```

**제가 제공한 프로젝트에는 `searchitfastnow.com`을 호출하는 코드가 없습니다.** 실제 프로젝트 소스에서도 해당 문자열이 없음을 확인했습니다.

특히 로그에:

```text
source=ext_operax15
```

가 들어가 있고 `content.js`가 나타나는 것으로 보아 **브라우저 확장 프로그램이 페이지에 JavaScript를 삽입하고 있을 가능성이 높습니다.**

Chrome에서 우선:

```text
Chrome
 → 확장 프로그램
 → 확장 프로그램 관리
```

로 들어가서 검색/홈페이지/새 탭 관련 확장 프로그램을 확인해 보십시오.

더 간단한 확인법은 **시크릿 창에서 확장 프로그램을 끈 상태로**

```text
http://localhost:5173
```

를 실행하는 것입니다.

이 CORS 오류는 현재 Perso의 `/api/session 400` 오류와는 별개입니다.

## 5. 지금 가장 먼저 해볼 것

새 버전으로 실행한 다음:

```text
http://localhost:5173/api/perso-settings
```

을 열어보는 것이 가장 중요합니다.

예를 들어 결과가:

```json
{
  "counts": {
    "modelStyles": 0,
    "prompts": 0,
    "llms": 3,
    "ttsTypes": 2,
    "sttTypes": 1
  }
}
```

라면 문제는 명확합니다.

```text
Perso API Key             정상
        ↓
TTS / STT 조회             정상
        ↓
Model Style               없음 ← 문제
Prompt                    없음 ← 문제
        ↓
Session 생성 불가능
```

반대로:

```json
{
  "counts": {
    "modelStyles": 3,
    "prompts": 2,
    "llms": 2,
    "ttsTypes": 4,
    "sttTypes": 2
  }
}
```

처럼 나온다면 **계정 리소스 문제는 아니며**, 그 다음 실제 `createSessionId()` 요청 오류를 추적하면 됩니다.

수정 버전에서는 오류 발생 시 이제 단순히

```text
Perso 계정에서 필요한 리소스를 찾지 못했습니다.
```

라고만 표시하지 않고,

```text
누락: model_style, prompt
```

처럼 **정확히 무엇이 없는지도 표시**하도록 바꿨습니다.
