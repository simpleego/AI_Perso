아닙니다. **조건부 분기는 프롬프트 내용에만 기반하지 않습니다.**

앞의 예제에서 질문 문자열을 검사한 것은 가장 간단한 실습 형태일 뿐입니다. `RunnableBranch`는 입력 데이터를 검사하는 **조건 함수 또는 Runnable**을 사용하며, 첫 번째로 `True`가 된 분기의 체인을 실행합니다. 모든 조건이 거짓이면 기본 체인이 실행됩니다. ([LangChain Reference Docs][1])

## 조건으로 사용할 수 있는 데이터

조건부 분기는 다음과 같은 값을 기준으로 동작할 수 있습니다.

* 질문의 단어나 의미
* 숫자, 점수, 가격
* 사용자 권한이나 등급
* 파일 형식
* API 호출 결과
* 데이터베이스 조회 결과
* 이전 체인의 분석 결과
* LLM이 분류한 카테고리
* 오류 발생 여부나 데이터 존재 여부

즉, 일반적인 Python의 `if-elif-else`처럼 생각하면 됩니다.

---

## 1. 문자열 기반 조건

앞에서 사용한 방식입니다.

```python
branch_chain = RunnableBranch(
    (
        lambda x: "파이썬" in x["question"],
        python_chain
    ),
    general_chain
)
```

```text
질문에 "파이썬" 포함 → python_chain
그 외                  → general_chain
```

---

## 2. 숫자에 따른 분기

학생 점수에 따라 서로 다른 피드백 체인을 실행할 수 있습니다.

```python
from langchain_core.runnables import RunnableBranch, RunnableLambda

excellent_chain = RunnableLambda(
    lambda x: f'{x["score"]}점: 우수한 성적입니다.'
)

normal_chain = RunnableLambda(
    lambda x: f'{x["score"]}점: 기본 개념을 복습하세요.'
)

support_chain = RunnableLambda(
    lambda x: f'{x["score"]}점: 기초 학습부터 다시 시작하세요.'
)

score_branch = RunnableBranch(
    (
        lambda x: x["score"] >= 80,
        excellent_chain
    ),
    (
        lambda x: x["score"] >= 60,
        normal_chain
    ),
    support_chain
)

print(score_branch.invoke({"score": 85}))
print(score_branch.invoke({"score": 70}))
print(score_branch.invoke({"score": 45}))
```

결과:

```text
85점: 우수한 성적입니다.
70점: 기본 개념을 복습하세요.
45점: 기초 학습부터 다시 시작하세요.
```

여기서는 프롬프트나 LLM을 전혀 사용하지 않습니다.

---

## 3. 사용자 권한에 따른 분기

```python
admin_chain = RunnableLambda(
    lambda x: "관리자 전용 기능을 실행합니다."
)

user_chain = RunnableLambda(
    lambda x: "일반 사용자 기능을 실행합니다."
)

role_branch = RunnableBranch(
    (
        lambda x: x["role"] == "admin",
        admin_chain
    ),
    user_chain
)

print(role_branch.invoke({
    "role": "admin"
}))
```

활용 사례:

```text
관리자 → 데이터 수정 체인
강사   → 강의자료 관리 체인
수강생 → 학습 콘텐츠 조회 체인
```

---

## 4. 파일 형식에 따른 분기

업로드한 파일 종류에 따라 다른 로더나 처리 체인을 사용할 수 있습니다.

```python
pdf_chain = RunnableLambda(
    lambda x: f'PDF 처리: {x["filename"]}'
)

csv_chain = RunnableLambda(
    lambda x: f'CSV 처리: {x["filename"]}'
)

text_chain = RunnableLambda(
    lambda x: f'일반 텍스트 처리: {x["filename"]}'
)

file_branch = RunnableBranch(
    (
        lambda x: x["filename"].lower().endswith(".pdf"),
        pdf_chain
    ),
    (
        lambda x: x["filename"].lower().endswith(".csv"),
        csv_chain
    ),
    text_chain
)

print(file_branch.invoke({
    "filename": "강의자료.pdf"
}))
```

실제 RAG 시스템에서는 다음처럼 사용할 수 있습니다.

```text
PDF  → PyPDFLoader
CSV  → CSVLoader
TXT  → TextLoader
기타 → 지원하지 않는 파일 안내
```

## 5. 데이터 존재 여부에 따른 분기

검색된 문서가 있는지 확인하여 RAG 답변과 일반 답변으로 나눌 수도 있습니다.

```python
rag_chain = RunnableLambda(
    lambda x: "검색 문서를 사용해 답변합니다."
)

normal_llm_chain = RunnableLambda(
    lambda x: "검색 문서가 없어 일반 지식으로 답변합니다."
)

document_branch = RunnableBranch(
    (
        lambda x: len(x.get("documents", [])) > 0,
        rag_chain
    ),
    normal_llm_chain
)

result = document_branch.invoke({
    "question": "지원금 신청 조건은?",
    "documents": ["검색된 문서 1", "검색된 문서 2"]
})

print(result)
```

```text
검색 문서 있음 → RAG 체인
검색 문서 없음 → 일반 LLM 체인
```

---

## 6. 이전 체인의 결과에 따른 분기

조건부 분기 앞에 분석 체인을 배치할 수도 있습니다.

```text
사용자 질문
    ↓
질문 분석 체인
    ↓
분석 결과: category
    ↓
RunnableBranch
 ├─ coding → 코딩 체인
 ├─ data   → 데이터 분석 체인
 └─ general → 일반 체인
```

이 경우 분기 조건은 사용자의 원래 질문이 아니라, **이전 체인이 생성한 분석 결과**입니다.

## 7. LLM 분류 결과를 이용한 의미 기반 분기

단순 키워드 방식에는 한계가 있습니다.

예를 들어 다음 질문에는 `"파이썬"`이라는 단어가 없지만 코딩 질문입니다.

```text
리스트에서 중복된 값을 제거하는 프로그램을 작성해줘.
```

이런 경우 LLM으로 질문 의도를 먼저 분류한 다음 분기할 수 있습니다.

```python
import os
import getpass

from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import (
    RunnableBranch,
    RunnablePassthrough
)

if not os.environ.get("OPENAI_API_KEY"):
    os.environ["OPENAI_API_KEY"] = getpass.getpass(
        "OpenAI API Key: "
    )

llm = ChatOpenAI(
    model="gpt-4o-mini",
    temperature=0
)

parser = StrOutputParser()
```

### 질문 분류 체인

```python
classification_prompt = ChatPromptTemplate.from_template(
    """
다음 질문을 반드시 하나의 카테고리로만 분류하세요.

카테고리:
- coding
- data
- general

질문:
{question}

카테고리:
"""
)

classification_chain = (
    classification_prompt
    | llm
    | parser
)
```

### 분야별 답변 체인

```python
coding_prompt = ChatPromptTemplate.from_template(
    """
당신은 프로그래밍 강사입니다.
예제 코드를 포함하여 설명하세요.

질문:
{question}
"""
)

data_prompt = ChatPromptTemplate.from_template(
    """
당신은 데이터 분석 강사입니다.
분석 절차와 활용 방법을 설명하세요.

질문:
{question}
"""
)

general_prompt = ChatPromptTemplate.from_template(
    """
비전공자도 이해할 수 있도록 쉽게 설명하세요.

질문:
{question}
"""
)

coding_chain = coding_prompt | llm | parser
data_chain = data_prompt | llm | parser
general_chain = general_prompt | llm | parser
```

### 분류 결과를 입력 데이터에 추가

```python
add_category_chain = RunnablePassthrough.assign(
    category=classification_chain
)
```

입력 데이터가 다음과 같이 변경됩니다.

```python
# 변경 전
{
    "question": "리스트에서 중복 값을 제거하는 방법은?"
}

# 변경 후
{
    "question": "리스트에서 중복 값을 제거하는 방법은?",
    "category": "coding"
}
```

### 조건부 분기

```python
branch_chain = RunnableBranch(
    (
        lambda x: x["category"].strip().lower() == "coding",
        coding_chain
    ),
    (
        lambda x: x["category"].strip().lower() == "data",
        data_chain
    ),
    general_chain
)
```

### 전체 체인 연결

```python
final_chain = add_category_chain | branch_chain

result = final_chain.invoke({
    "question": "리스트에서 중복된 값을 제거하는 프로그램을 작성해줘."
})

print(result)
```

이 구조에서는 다음과 같이 처리됩니다.

```text
질문 입력
   ↓
LLM이 질문 의도 분류
   ↓
category = coding
   ↓
코딩 체인 실행
```

## 조건 설정 방식 비교

| 방식       | 조건 예시                 | 장점            | 단점                  |
| -------- | --------------------- | ------------- | ------------------- |
| 규칙 기반    | 키워드, 숫자, 파일 확장자       | 빠르고 결과가 일정함   | 복잡한 의미 판단이 어려움      |
| 데이터 기반   | 사용자 등급, DB 결과, API 결과 | 업무 규칙 구현에 적합  | 입력 데이터가 필요함         |
| 이전 체인 기반 | 검색 결과, 분석 결과          | 복합 워크플로 구성 가능 | 구조가 복잡해질 수 있음       |
| LLM 기반   | 질문 의도, 감정, 주제 분류      | 문맥과 의미를 판단함   | 비용과 지연이 발생하고 오분류 가능 |

## 핵심 정리

```text
RunnableBranch의 조건
    ├─ 프롬프트 내용
    ├─ 문자열·키워드
    ├─ 숫자·점수
    ├─ 사용자 정보
    ├─ 파일 및 데이터 형식
    ├─ API·DB 결과
    ├─ 검색 결과
    └─ 이전 LLM 체인의 출력
```

따라서 `RunnableBranch`는 **프롬프트 전용 분기 기능이 아니라, 입력 데이터와 처리 결과를 기준으로 Runnable을 선택하는 범용 라우팅 기능**이라고 이해하는 것이 정확합니다. `RunnableBranch`는 조건을 순서대로 평가하므로 여러 조건이 동시에 참일 수 있다면 더 구체적인 조건을 앞쪽에 배치해야 합니다. ([LangChain Reference Docs][1])
