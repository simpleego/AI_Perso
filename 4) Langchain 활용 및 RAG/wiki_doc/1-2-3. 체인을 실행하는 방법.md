# 1-2-3. 체인을 실행하는 방법
> LangChain의 `invoke`, `batch`, `stream`은 모두 **체인 또는 모델을 실행하는 방법**이지만, 다음 세 가지 기준에서 차이가 있습니다.

1. 입력을 한 개 처리하는가, 여러 개 처리하는가
2. 결과를 한 번에 받는가, 생성되는 즉시 받는가
3. 실행이 끝날 때까지 기다리는가, 다른 작업을 함께 처리하는가

LangChain의 모든 `Runnable`은 일반적으로 동기 메서드와 `a`가 붙은 비동기 메서드를 함께 제공합니다. ([LangChain Reference Docs][1])

## 1. 전체 비교

| 동기 메서드     | 비동기 메서드     |   입력 | 결과 전달          | 주요 목적         |
| ---------- | ----------- | ---: | -------------- | ------------- |
| `invoke()` | `ainvoke()` |   1개 | 완료 후 한 번에 반환   | 일반적인 단일 질문 처리 |
| `batch()`  | `abatch()`  | 여러 개 | 전체 완료 후 리스트 반환 | 다수 작업의 병렬 처리  |
| `stream()` | `astream()` |   1개 | 생성되는 조각을 순차 반환 | 실시간 응답 출력     |

핵심적으로 다음과 같이 기억하면 됩니다.

```text
invoke  = 하나를 처리
batch   = 여러 개를 처리
stream  = 하나의 결과를 나누어 전달

a + 메서드 = 비동기 방식으로 실행
```

---

# 2. `invoke()`와 `ainvoke()`

## `invoke()`

하나의 입력을 전달하고, 전체 결과가 완성될 때까지 기다렸다가 반환합니다.

```python
result = chain.invoke({
    "question": "LangChain이란 무엇인가?"
})

print(result)
```

실행 흐름은 다음과 같습니다.

```text
질문 1개 입력
    ↓
체인 실행
    ↓
전체 답변 생성 완료
    ↓
결과 반환
```

예를 들어 LLM이 답변을 완성하는 데 5초가 걸린다면, 프로그램은 일반적으로 5초 후에 전체 답변을 받습니다.

### 적합한 응용 분야

* 단일 질문에 대한 답변
* 간단한 챗봇 테스트
* 문서 한 개 요약
* 번역 요청 한 건
* 분류 작업 한 건
* 체인의 실행 결과 확인

---

## `ainvoke()`

`invoke()`의 비동기 버전입니다.

```python
result = await chain.ainvoke({
    "question": "LangChain이란 무엇인가?"
})

print(result)
```

결과 형태는 `invoke()`와 거의 같습니다. 차이는 결과의 내용이 아니라 **프로그램의 대기 방식**입니다.

```text
질문 1개 실행 시작
    ↓
LLM 응답을 기다리는 동안
다른 비동기 작업 수행 가능
    ↓
답변 완료
    ↓
결과 반환
```

LangChain에서 `ainvoke()`는 하나의 입력을 하나의 출력으로 변환하는 비동기 인터페이스입니다. 일부 Runnable은 자체적인 비동기 실행을 제공하고, 기본 구현에서는 동기 메서드를 스레드 풀을 통해 실행할 수도 있습니다. ([LangChain Reference Docs][1])

### 적합한 응용 분야

* FastAPI 비동기 서버
* 여러 사용자가 동시에 질문하는 챗봇
* 웹 API 호출과 LLM 호출을 함께 수행하는 서비스
* 데이터베이스, 검색 API, LLM을 병렬 호출하는 시스템
* 비동기 에이전트

### 중요한 점

`ainvoke()`가 반드시 **질문 한 건의 답변 속도를 더 빠르게 만드는 것은 아닙니다.**

예를 들어 하나의 LLM 요청이 5초 걸린다면:

```text
invoke()  → 약 5초
ainvoke() → 약 5초
```

단, `ainvoke()`는 기다리는 동안 다른 요청을 처리할 수 있으므로 **동시 사용자 처리량과 서버 효율**을 높이는 데 유리합니다.

# 3. `batch()`와 `abatch()`

## `batch()`

여러 개의 입력을 한 번에 전달합니다.

```python
questions = [
    {"question": "AI란 무엇인가?"},
    {"question": "LLM이란 무엇인가?"},
    {"question": "RAG란 무엇인가?"}
]

results = chain.batch(questions)

for result in results:
    print(result)
```

입력과 출력 구조는 다음과 같습니다.

```text
입력 목록
[
    질문 1,
    질문 2,
    질문 3
]
    ↓
여러 작업 실행
    ↓
결과 목록
[
    답변 1,
    답변 2,
    답변 3
]
```

LangChain의 기본 `batch()` 구현은 여러 입력에 대해 `invoke()`를 스레드 풀에서 병렬 실행합니다. 따라서 네트워크 API 호출과 같이 기다리는 시간이 많은 I/O 중심 작업에 적합합니다. 다만 사용하는 모델이나 API가 자체 배치 기능을 제공하면 해당 Runnable이 더 효율적인 방식으로 재정의할 수 있습니다. ([LangChain Reference Docs][2])

### 순차 처리와 비교

다음 코드는 순차 실행입니다.

```python
results = []

for question in questions:
    result = chain.invoke(question)
    results.append(result)
```

각 요청이 3초 걸린다고 가정하면:

```text
질문 1: 3초
질문 2: 3초
질문 3: 3초

총 약 9초
```

`batch()`가 세 요청을 병렬로 처리할 수 있다면 다음과 같은 구조가 됩니다.

```text
질문 1 ─┐
질문 2 ─┼─ 동시에 실행 → 결과 목록
질문 3 ─┘
```

이상적인 경우 전체 시간이 약 3초에 가까워질 수 있지만, 실제 시간은 API 동시성 제한, 네트워크, 모델 처리량 등에 따라 달라집니다.

### 적합한 응용 분야

* 여러 문서 동시 요약
* 여러 문장 번역
* 데이터셋의 감정 분석
* 학생 답안 일괄 평가
* 여러 상품 설명 생성
* 테스트 질문 일괄 실행
* LLM 모델 성능 평가
* 다수 문서의 분류 및 태깅

---

## `abatch()`

`batch()`의 비동기 버전입니다.

```python
questions = [
    {"question": "AI란 무엇인가?"},
    {"question": "LLM이란 무엇인가?"},
    {"question": "RAG란 무엇인가?"}
]

results = await chain.abatch(questions)

for result in results:
    print(result)
```

기본 `abatch()`는 여러 `ainvoke()` 작업을 `asyncio.gather()` 방식으로 병렬 실행합니다. 특히 API 호출, 검색, 데이터베이스 접근 등 I/O 중심 Runnable에서 순차적인 `ainvoke()` 호출보다 효율적일 수 있습니다. ([LangChain Reference Docs][3])

### `batch()`와 `abatch()` 차이

| 구분        | `batch()`      | `abatch()`         |
| --------- | -------------- | ------------------ |
| 실행 방식     | 동기 병렬 처리       | 비동기 병렬 처리          |
| 호출 결과     | 일반 리스트         | `await` 후 리스트      |
| 호출 중 프로그램 | 현재 흐름이 대기      | 다른 비동기 작업 수행 가능    |
| 적합한 환경    | 일반 Python 프로그램 | FastAPI, 비동기 서버    |
| 내부 기본 방식  | 스레드 풀          | `asyncio.gather()` |

### 동시 요청 수 제한

너무 많은 요청을 동시에 보내면 API의 속도 제한에 걸릴 수 있으므로 `max_concurrency`를 설정할 수 있습니다.

```python
results = await chain.abatch(
    questions,
    config={
        "max_concurrency": 3
    }
)
```

의미는 다음과 같습니다.

```text
전체 질문: 100개
동시 실행 제한: 3개

→ 한 번에 최대 3개씩 처리
```

# 4. `stream()`과 `astream()`

## `stream()`

하나의 입력에 대한 결과를 완성된 뒤 한 번에 받는 것이 아니라, 생성되는 조각 단위로 받습니다.

```python
for chunk in chain.stream({
    "question": "생성형 AI의 발전 과정을 설명해줘"
}):
    print(chunk, end="", flush=True)
```

실행 결과는 다음처럼 나타납니다.

```text
생성형
생성형 AI는
생성형 AI는 데이터를
생성형 AI는 데이터를 기반으로...
```

실제로 반환되는 단위는 Runnable에 따라 토큰, 문자열 조각, 메시지 조각 또는 구조화된 이벤트가 될 수 있습니다.

실행 흐름은 다음과 같습니다.

```text
질문 입력
    ↓
첫 번째 결과 조각 생성 → 즉시 화면 출력
    ↓
두 번째 결과 조각 생성 → 즉시 화면 출력
    ↓
세 번째 결과 조각 생성 → 즉시 화면 출력
    ↓
응답 완료
```

LangChain의 `stream()`은 단일 입력으로부터 생성되는 출력을 순차적으로 전달하는 인터페이스입니다. ([LangChain Reference Docs][1])

### 적합한 응용 분야

* ChatGPT와 같은 실시간 챗봇
* 긴 보고서 생성
* 실시간 번역 출력
* 음성 챗봇의 문장 단위 응답
* LLM 답변 진행 상황 표시
* 사용자 대기시간 체감 개선

### `invoke()`와 비교

`invoke()`:

```text
[5초 대기] → 전체 답변 표시
```

`stream()`:

```text
[1초] 첫 단어
[2초] 다음 문장
[3초] 추가 문장
[5초] 답변 완료
```

전체 처리 시간이 크게 줄지 않더라도, 사용자는 첫 결과를 더 빨리 보기 때문에 응답이 빠르다고 느끼게 됩니다.

---

## `astream()`

`stream()`의 비동기 버전입니다.

```python
async for chunk in chain.astream({
    "question": "생성형 AI의 발전 과정을 설명해줘"
}):
    print(chunk, end="", flush=True)
```

일반 `for`가 아니라 `async for`를 사용합니다.

```python
for chunk in chain.stream(input):
    ...
```

```python
async for chunk in chain.astream(input):
    ...
```

### 적합한 응용 분야

* FastAPI의 스트리밍 응답
* 여러 사용자가 접속하는 실시간 챗봇
* WebSocket 기반 챗봇
* 서버 전송 이벤트, SSE 기반 응답
* 실시간 음성 AI
* 비동기 에이전트 진행 상황 출력

---

# 5. 스트리밍에서 주의할 점

`stream()`이나 `astream()`을 호출한다고 해서 모든 체인이 반드시 토큰 단위로 스트리밍되는 것은 아닙니다.

체인의 구성 요소 중 하나가 스트리밍을 지원하지 않으면 해당 구성 요소의 실행이 끝날 때까지 출력이 지연될 수 있습니다. LangChain의 기본 `stream()` 구현도 별도의 스트리밍 구현이 없는 경우 내부적으로 `invoke()` 결과를 반환하는 방식으로 동작할 수 있습니다. ([LangChain Reference Docs][3])

예를 들어 다음 체인이 있다고 가정하겠습니다.

```text
프롬프트
   ↓
LLM
   ↓
일반 Python 함수
   ↓
출력 파서
```

일반 Python 함수가 전체 LLM 결과를 받아야만 실행될 수 있다면:

```text
LLM 생성 중
    ↓
Python 함수가 전체 결과를 기다림
    ↓
함수 처리 완료
    ↓
그 이후 결과 출력
```

따라서 실시간 스트리밍이 중요한 시스템에서는 체인을 구성하는 각 Runnable이 스트리밍을 지원하는지 확인해야 합니다.

# 6. 동기와 비동기의 핵심 차이

## 동기 방식

현재 작업이 끝날 때까지 다음 작업으로 넘어가지 않습니다.

```python
result1 = chain.invoke(input1)
result2 = chain.invoke(input2)
result3 = chain.invoke(input3)
```

실행 순서:

```text
작업 1 완료
    ↓
작업 2 완료
    ↓
작업 3 완료
```

## 비동기 방식

작업이 외부 API의 응답을 기다리는 동안 다른 작업을 수행할 수 있습니다.

```python
import asyncio

result1, result2, result3 = await asyncio.gather(
    chain.ainvoke(input1),
    chain.ainvoke(input2),
    chain.ainvoke(input3)
)
```

실행 구조:

```text
작업 1 ─────────┐
작업 2 ─────────┼─ 동시에 대기 및 실행
작업 3 ─────────┘
```

단, 여러 입력을 같은 체인에 전달한다면 직접 `asyncio.gather()`를 작성하기보다 다음처럼 `abatch()`를 사용하는 것이 간단합니다.

```python
results = await chain.abatch([
    input1,
    input2,
    input3
])
```

# 7. 실무 상황별 선택

## 상황 1: 사용자가 질문 한 개를 입력한다

```python
result = chain.invoke(question)
```

추천 메서드:

```text
invoke()
```

간단한 콘솔 프로그램이나 테스트 코드에 적합합니다.

---

## 상황 2: 웹 서버에서 질문 한 개를 처리한다

```python
result = await chain.ainvoke(question)
```

추천 메서드:

```text
ainvoke()
```

한 사용자의 LLM 응답을 기다리는 동안 다른 사용자의 요청을 처리할 수 있습니다.

---

## 상황 3: 문서 100개를 요약한다

```python
results = chain.batch(documents)
```

또는:

```python
results = await chain.abatch(documents)
```

추천 메서드:

```text
batch() 또는 abatch()
```

일반 스크립트는 `batch()`, 비동기 서버나 비동기 파이프라인은 `abatch()`가 적합합니다.

---

## 상황 4: 챗봇 답변을 실시간으로 보여준다

```python
for chunk in chain.stream(question):
    print(chunk, end="")
```

추천 메서드:

```text
stream()
```

콘솔, Streamlit 또는 간단한 Gradio 앱에서 사용할 수 있습니다.

---

## 상황 5: 여러 사용자가 접속하는 실시간 챗봇

```python
async for chunk in chain.astream(question):
    ...
```

추천 메서드:

```text
astream()
```

FastAPI, WebSocket, SSE 기반 서비스에 적합합니다.

# 8. 최종 선택 기준

```text
입력이 한 개인가?
 ├─ 결과를 한 번에 받아도 된다
 │    ├─ 일반 프로그램 → invoke()
 │    └─ 비동기 서버   → ainvoke()
 │
 └─ 결과를 실시간으로 보여준다
      ├─ 일반 프로그램 → stream()
      └─ 비동기 서버   → astream()

입력이 여러 개인가?
 ├─ 일반 프로그램 → batch()
 └─ 비동기 서버   → abatch()
```

## 한 문장 정리

* `invoke` / `ainvoke`: **질문 한 건을 처리하고 완성된 결과를 받는다.**
* `batch` / `abatch`: **여러 입력을 병렬로 처리하고 결과 목록을 받는다.**
* `stream` / `astream`: **한 입력의 결과를 생성되는 즉시 나누어 받는다.**
* `a`가 붙은 메서드: **대기 중 다른 작업을 처리할 수 있는 비동기 실행 방식이다.**
