# 멀티체인 조건부 분기 숫자값의 결과 사용

> 둘 다 가능합니다. 핵심은 `RunnableBranch`가 **성적이 어디에서 만들어졌는지 확인하지 않고**, 자신에게 전달된 입력 데이터의 `score` 값만 검사한다는 점입니다.
> 앞서 제시한 코드는 다음과 같았습니다.

```python
score_branch.invoke({"score": 85})
```

여기서 `85`는 순수 파이썬 계산 결과도 아니고 LangChain 도구 결과도 아닙니다. 실습을 단순화하기 위해 **직접 입력한 값**입니다.

```text
직접 입력한 점수 85
        ↓
{"score": 85}
        ↓
RunnableBranch
        ↓
80점 이상 체인 실행
```

`RunnableBranch`는 조건을 순서대로 검사하고, 처음으로 `True`가 나온 분기를 실행합니다. 조건이 모두 거짓이면 기본 분기를 실행합니다. ([LangChain Reference Docs][1])

# 1. 순수 파이썬 계산 결과를 연결하는 경우

온라인 시험에서 정답 개수와 전체 문제 수를 받아 점수를 계산한다고 가정하겠습니다.

```text
정답 수와 전체 문제 수
        ↓
파이썬 함수로 점수 계산
        ↓
{"score": 85.0}
        ↓
RunnableBranch
        ↓
성적별 피드백
```

## 실습 코드

```python
from langchain_core.runnables import RunnableBranch, RunnableLambda


# --------------------------------------------------
# 1. 점수 계산: 순수 파이썬 함수
# --------------------------------------------------
def calculate_score(data: dict) -> dict:
    correct = data["correct"]
    total = data["total"]

    if total <= 0:
        raise ValueError("전체 문제 수는 1 이상이어야 합니다.")

    score = correct / total * 100

    return {
        "student_name": data["student_name"],
        "correct": correct,
        "total": total,
        "score": round(score, 1)
    }


# --------------------------------------------------
# 2. 성적별 처리 함수
# --------------------------------------------------
def excellent_feedback(data: dict) -> str:
    return (
        f'{data["student_name"]}: {data["score"]}점\n'
        "우수한 성적입니다. 심화 학습을 진행하세요."
    )


def normal_feedback(data: dict) -> str:
    return (
        f'{data["student_name"]}: {data["score"]}점\n'
        "기본 개념을 조금 더 복습하세요."
    )


def support_feedback(data: dict) -> str:
    return (
        f'{data["student_name"]}: {data["score"]}점\n'
        "기초 개념부터 단계적으로 다시 학습하세요."
    )


# --------------------------------------------------
# 3. 조건부 분기
# --------------------------------------------------
score_branch = RunnableBranch(
    (
        lambda data: data["score"] >= 80,
        RunnableLambda(excellent_feedback)
    ),
    (
        lambda data: data["score"] >= 60,
        RunnableLambda(normal_feedback)
    ),
    RunnableLambda(support_feedback)
)


# --------------------------------------------------
# 4. 점수 계산 → 조건부 분기
# --------------------------------------------------
score_chain = (
    RunnableLambda(calculate_score)
    | score_branch
)


# --------------------------------------------------
# 5. 실행
# --------------------------------------------------
result = score_chain.invoke({
    "student_name": "홍길동",
    "correct": 17,
    "total": 20
})

print(result)
```

실행 결과:

```text
홍길동: 85.0점
우수한 성적입니다. 심화 학습을 진행하세요.
```

`RunnableLambda`는 일반 파이썬 함수를 LangChain의 Runnable로 감싸므로, 파이썬 계산 함수를 `|` 연산자로 다른 체인과 연결할 수 있습니다. ([LangChain Reference Docs][2])

이 방식에는 LLM도 없고 프롬프트도 없으며, LangChain 도구도 사용하지 않습니다.

# 2. 데이터베이스 조회 결과를 연결하는 경우

학교 데이터베이스에 이미 학생의 점수가 저장되어 있다고 가정하겠습니다.

```text
학생 번호 입력
        ↓
데이터베이스에서 성적 조회
        ↓
{"student_name": "홍길동", "score": 85}
        ↓
RunnableBranch
        ↓
성적별 피드백
```

실습에서는 실제 데이터베이스 대신 딕셔너리로 구현할 수 있습니다.

```python
from langchain_core.runnables import RunnableLambda


student_database = {
    "S001": {
        "student_name": "홍길동",
        "score": 85
    },
    "S002": {
        "student_name": "김영희",
        "score": 72
    },
    "S003": {
        "student_name": "이철수",
        "score": 48
    }
}


def get_student_score(data: dict) -> dict:
    student_id = data["student_id"]

    if student_id not in student_database:
        raise ValueError("등록되지 않은 학생 번호입니다.")

    return student_database[student_id]


database_score_chain = (
    RunnableLambda(get_student_score)
    | score_branch
)


result = database_score_chain.invoke({
    "student_id": "S002"
})

print(result)
```

실행 결과:

```text
김영희: 72점
기본 개념을 조금 더 복습하세요.
```

실제 프로젝트에서는 `get_student_score()` 안에서 SQLite, MySQL, PostgreSQL 또는 학교 LMS API를 호출할 수 있습니다.

# 3. LangChain 도구 실행 결과를 연결하는 경우

같은 데이터베이스 조회 함수를 LangChain의 `@tool`로 정의할 수도 있습니다.

LangChain 도구는 명확한 입력과 출력을 갖는 호출 가능한 함수이며, 데이터베이스 조회, API 호출, 코드 실행 같은 외부 작업에 사용됩니다. 도구는 문자열뿐 아니라 `dict` 같은 구조화된 객체를 반환할 수 있습니다. ([Docs by LangChain][3])

## 도구 정의

```python
from langchain.tools import tool


@tool
def get_score_tool(student_id: str) -> dict:
    """학생 번호를 이용하여 학생 이름과 성적을 조회합니다."""

    if student_id not in student_database:
        return {
            "found": False,
            "student_name": "알 수 없음",
            "score": 0
        }

    student = student_database[student_id]

    return {
        "found": True,
        "student_name": student["student_name"],
        "score": student["score"]
    }
```

## 도구를 직접 실행한 후 분기

```python
tool_result = get_score_tool.invoke({
    "student_id": "S001"
})

print("도구 결과:", tool_result)

branch_result = score_branch.invoke(tool_result)

print("\n분기 결과:")
print(branch_result)
```

처리 과정은 다음과 같습니다.

```text
get_score_tool.invoke(...)
        ↓
{
    "found": True,
    "student_name": "홍길동",
    "score": 85
}
        ↓
score_branch.invoke(...)
        ↓
우수 성적 체인
```

# 4. 도구 실행과 분기를 하나의 체인으로 연결

도구 실행을 `RunnableLambda` 안에 넣어 전체 흐름을 하나로 만들 수도 있습니다.

```python
def execute_score_tool(data: dict) -> dict:
    return get_score_tool.invoke({
        "student_id": data["student_id"]
    })


tool_score_chain = (
    RunnableLambda(execute_score_tool)
    | score_branch
)


result = tool_score_chain.invoke({
    "student_id": "S003"
})

print(result)
```

실행 결과:

```text
이철수: 48점
기초 개념부터 단계적으로 다시 학습하세요.
```

# 5. 파이썬 함수와 LangChain 도구의 차이

## 순수 파이썬 함수

```python
def calculate_score(data):
    return {"score": 85}
```

개발자가 실행 순서를 직접 결정합니다.

```python
score_chain = RunnableLambda(calculate_score) | score_branch
```

적합한 상황은 다음과 같습니다.

* 정답 수로 점수 계산
* 평균, 합계, 비율 계산
* 데이터 전처리
* 정해진 비즈니스 규칙 처리
* 반드시 실행해야 하는 작업

## LangChain 도구

```python
@tool
def get_score_tool(student_id: str) -> dict:
    ...
```

도구는 에이전트나 LLM에 제공할 수 있도록 이름, 설명, 입력 스키마를 갖습니다. 모델은 대화 문맥을 보고 필요한 도구와 입력값을 선택할 수 있습니다. ([Docs by LangChain][3])

적합한 상황은 다음과 같습니다.

* 학생 번호를 이용한 DB 조회
* 외부 LMS API 호출
* 시험 결과 파일 조회
* 웹 검색
* 계산기, 검색기, SQL 실행기
* 에이전트가 상황에 따라 선택해야 하는 기능

# 6. 에이전트가 도구를 선택하는 경우

다음과 같은 사용자 질문을 처리한다고 가정하겠습니다.

```text
사용자: S001 학생의 성적을 확인하고 학습 방향을 추천해줘.
```

에이전트 방식에서는 다음과 같이 처리될 수 있습니다.

```text
사용자 질문
    ↓
LLM이 질문 해석
    ↓
get_score_tool 호출 결정
    ↓
학생 점수 조회
    ↓
점수 결과
    ↓
조건부 분기
    ↓
학습 피드백 생성
```

다만 **성적 계산이나 합격 여부처럼 규칙이 명확하고 중요한 작업**은 LLM이 도구 호출 여부를 결정하게 하기보다, 프로그램이 도구를 반드시 실행하도록 만드는 편이 안정적입니다.

예를 들면 다음 구조가 적합합니다.

```text
학생 번호 입력
    ↓
프로그램이 성적 조회 도구를 반드시 실행
    ↓
RunnableBranch로 합격·불합격 결정
    ↓
필요한 경우에만 LLM이 피드백 문장 생성
```

# 7. LLM은 어느 부분에 사용하는가

점수 계산과 등급 결정은 파이썬으로 하고, 최종 피드백만 LLM으로 생성하는 구조가 실용적입니다.

```text
정답 데이터
    ↓
파이썬: 점수 계산
    ↓
RunnableBranch: 수준 결정
    ↓
LLM: 수준별 맞춤 피드백 생성
```

예를 들어 분기 결과에 따라 서로 다른 프롬프트 체인을 실행할 수 있습니다.

```python
score_branch = RunnableBranch(
    (
        lambda data: data["score"] >= 80,
        excellent_llm_chain
    ),
    (
        lambda data: data["score"] >= 60,
        normal_llm_chain
    ),
    support_llm_chain
)
```

이때 역할은 다음과 같이 분리됩니다.

```text
점수 계산       → 순수 파이썬
성적 구간 판단  → RunnableBranch
피드백 문장 생성 → LLM 프롬프트 체인
```

## 결론

앞서 제시한 `"숫자에 따른 분기"` 예시는 단순히 다음처럼 **외부에서 점수가 이미 전달된 상황**이었습니다.

```python
score_branch.invoke({"score": 85})
```

실제 프로젝트에서는 세 가지 방식이 모두 가능합니다.

```text
① 직접 입력
   {"score": 85}

② 순수 파이썬 계산
   정답 수 → 점수 계산 → RunnableBranch

③ LangChain 도구 실행
   DB·API 조회 → 점수 반환 → RunnableBranch
```

가장 중요한 원칙은 다음과 같습니다.

> `RunnableBranch`는 점수가 파이썬에서 계산됐는지, 데이터베이스에서 조회됐는지, LangChain 도구에서 반환됐는지를 구분하지 않습니다. 최종적으로 `{"score": 숫자}` 형태의 데이터만 전달되면 분기할 수 있습니다.
