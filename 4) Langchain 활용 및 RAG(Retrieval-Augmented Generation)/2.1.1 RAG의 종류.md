# 2.1.1 RAG의 종류

<img width="800"  alt="image" src="https://github.com/user-attachments/assets/5e930f38-1064-422c-a446-d8b2e2f689f5" />
아래는 **이미지에 나온 9가지 RAG 기법**을 기준으로 정리한 것입니다. 실제 프로젝트에서는 이 9가지가 완전히 독립된 구조라기보다, 서로 조합해서 사용하는 경우가 많습니다.

## RAG 9가지 유형 정리

| RAG 유형                    | 핵심 개념                                              | 장점                                                    | 단점                                                     | 주요 응용 분야                                        |
| ------------------------- | -------------------------------------------------- | ----------------------------------------------------- | ------------------------------------------------------ | ----------------------------------------------- |
| **1. Standard RAG**       | 사용자의 질문을 벡터DB에서 검색하고, 관련 문서를 LLM에 넣어 답변 생성         | 구조가 단순하고 구현이 쉬움. LangChain, LlamaIndex 등으로 빠르게 개발 가능. | 검색 품질이 낮으면 답변도 부정확함. 문맥이 부족하거나 잘못된 문서를 가져오면 환각 가능성 있음. | FAQ 챗봇, 사내 문서 검색, 교육자료 질의응답, 매뉴얼 기반 상담          |
| **2. Multi-Source RAG**   | PDF, DB, 웹문서, API, 사내 시스템 등 여러 지식 소스를 함께 검색        | 다양한 데이터 출처를 통합할 수 있음. 하나의 챗봇이 여러 업무 영역을 다룰 수 있음.      | 데이터 소스별 형식이 달라 전처리와 통합이 복잡함. 출처 간 충돌이 발생할 수 있음.        | 기업 지식관리, 공공기관 민원 상담, 의료/법률 문서 통합 검색, 교육 플랫폼     |
| **3. Agentic RAG**        | LLM Agent가 어떤 도구나 DB를 사용할지 스스로 판단하며 검색·추론 수행       | 단순 검색을 넘어 DB 조회, API 호출, 계산, 문서 검색 등을 능동적으로 수행 가능     | Agent가 잘못된 도구를 선택하거나 불필요한 단계를 수행할 수 있음. 비용과 지연시간 증가 가능 | 업무 자동화 비서, ERP/CRM 연동 챗봇, 정책 상담, 데이터 분석 자동화     |
| **4. Fusion RAG**         | 여러 검색 결과 또는 여러 쿼리 결과를 결합하여 더 좋은 문맥을 구성             | 검색 정확도와 재현율을 높일 수 있음. 하나의 검색 방식이 놓치는 정보를 보완 가능        | 검색·랭킹·병합 과정이 복잡함. 중복 문서나 불필요한 문맥이 늘어날 수 있음             | 논문 검색, 법률 판례 검색, 기술 문서 검색, 고품질 리서치 챗봇           |
| **5. Interactive RAG**    | 사용자와 상호작용하면서 질문을 보완하거나 검색 범위를 조정                   | 사용자의 의도를 점진적으로 명확히 할 수 있음. 애매한 질문에 강함                 | 대화 설계가 복잡함. 사용자가 여러 번 응답해야 해서 사용성이 떨어질 수 있음            | 학습 도우미, 상담 챗봇, 진단형 서비스, 요구사항 분석 도구              |
| **6. Contextual RAG**     | 현재 질문뿐 아니라 이전 대화, 사용자 상황, 메타데이터, 주변 문맥을 함께 반영      | 대화형 서비스에서 자연스럽고 일관된 답변 가능. 같은 질문도 상황에 맞게 답변 가능        | 대화 이력 관리가 필요함. 오래된 문맥이 잘못 반영되면 답변이 왜곡될 수 있음            | 개인화 학습 튜터, 고객상담 챗봇, 의료 상담 보조, 장기 대화형 AI 비서      |
| **7. Multi-Pass RAG**     | 한 번만 검색하지 않고, 여러 단계로 검색 → 답변 → 재검색 → 보완을 반복        | 복잡한 질문이나 다단계 추론 문제에 강함. 답변 품질을 점진적으로 개선 가능            | 처리 시간이 길어짐. 검색 횟수가 많아 비용 증가. 설계가 복잡함                   | 복합 질의응답, 연구 보고서 작성, 법률 검토, 데이터 기반 의사결정 지원       |
| **8. Feedback Based RAG** | 사용자 피드백, 평가 지표, LLM-as-a-Judge 등을 이용해 검색·답변 품질을 개선 | 운영하면서 점점 성능을 개선할 수 있음. 실제 사용자 만족도를 반영 가능              | 피드백 데이터 수집과 평가 체계가 필요함. 잘못된 피드백이 누적되면 품질 저하 가능         | 고객센터 챗봇 개선, 교육용 AI 튜터 고도화, 사내 지식봇 운영, 서비스 품질 관리 |
| **9. Adversarial RAG**    | 악의적 질문, 잘못된 문서, 프롬프트 인젝션, 공격성 데이터에 견디도록 설계         | 보안성과 신뢰성을 높일 수 있음. 위험한 문서나 조작된 검색 결과에 강함              | 구현 난도가 높음. 보안 필터, 검증기, 평가셋 구축이 필요함                     | 금융/의료/법률 AI, 보안 민감 챗봇, 프롬프트 인젝션 방어, RAG 취약점 테스트 |

## 쉽게 구분하면

| 목적                    | 적합한 RAG                |
| --------------------- | ---------------------- |
| 가장 기본적인 문서 기반 챗봇      | **Standard RAG**       |
| 여러 자료 출처를 동시에 활용      | **Multi-Source RAG**   |
| API, DB, 도구까지 자동으로 사용 | **Agentic RAG**        |
| 검색 품질을 높이고 싶을 때       | **Fusion RAG**         |
| 사용자와 질문을 주고받으며 보완     | **Interactive RAG**    |
| 대화 이력과 상황을 반영         | **Contextual RAG**     |
| 복잡한 문제를 여러 단계로 해결     | **Multi-Pass RAG**     |
| 운영 중 성능을 계속 개선        | **Feedback Based RAG** |
| 보안과 신뢰성이 중요한 서비스      | **Adversarial RAG**    |

## 교육용 프로젝트 관점 추천 순서

RAG를 처음 교육하거나 프로젝트로 구현한다면 다음 순서가 좋습니다.

**1단계:** Standard RAG
→ PDF 문서 업로드, 임베딩, 벡터DB 검색, LLM 답변 생성

**2단계:** Multi-Source RAG
→ PDF + 웹문서 + CSV + DB를 함께 검색

**3단계:** Contextual RAG
→ 이전 대화 이력을 반영하는 챗봇 구현

**4단계:** Fusion RAG
→ 키워드 검색과 벡터 검색을 결합하는 Hybrid Search 구현

**5단계:** Agentic RAG
→ 검색 도구, DB 조회 도구, 계산 도구를 Agent가 선택하도록 구성

**6단계:** Feedback Based RAG
→ 답변 평가, 사용자 피드백, 검색 품질 개선 루프 추가

프로젝트 난이도 기준으로 보면 **Standard RAG → Multi-Source RAG → Contextual RAG → Fusion RAG → Multi-Pass RAG → Agentic RAG → Feedback Based RAG → Adversarial RAG** 순서로 확장하는 것이 가장 자연스럽습니다.
